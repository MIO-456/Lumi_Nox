# 文档地图

> **何时读**：你想知道"这件事该看哪份文档"，或准备新增 / 删除一份文档。
> **何时不用读**：已经知道自己要读哪一篇，直接去读。
> **复核**：`docs/` 新增 / 删除文件或入口变化时；维护者也可定期检查失效内容。

## 为什么不是一个大文件

把所有规则塞进 `AGENTS.md` 会出现五个可预期的问题：吃上下文预算、关键约束被埋在中间而忽略、硬约束与建议分不清、只增不减、新旧规则互相矛盾。所以这里按"用什么、什么时候用"拆开：

```
L1  入口      AGENTS.md            简短      概览 + 必要约束 + 文档索引
L2  专题      docs/*.md            按主题    说明行为、边界和使用方法
L3  协作      Issues / PR          按任务    范围、认领、讨论与验证证据
              feature_list.json    可选      已发布或待讨论的里程碑索引
              progress.md          按发布    公开进度与历史验证记录
L4  验证      init.sh / init.ps1   —         编译 + 测试 + 文档体检
```

一条规则只在一个地方定义。入口文件写"必须遵守"，专题文档写"怎么做、为什么、什么时候可以删"。

## 每篇文档的元信息

专题文档可以在标题下用三行引用块说明阅读条件。它帮助读者定位，简短说明不必为了模板增加重复内容：

```markdown
> **何时读**：<触发条件，具体到任务>。
> **何时不用读**：<避免误加载的场景>。
> **复核**：<时间点 或 明确的失效信号>。
```

- **何时读**决定路由表能否工作：写得含糊，agent 就只能在错误的时间加载错误的文档。
- **复核**是过期机制。没有失效信号的文档会永久留存，这正是"指令膨胀"的来源。
- 判断标准：如果删掉这篇文档，读者会犯什么错？答不上来就该删。

## 写作规则

1. **一篇围绕一个主题**。过长时检查是否可以拆分；行数检查是提示，不因超过固定行数强制拆散完整说明。
2. **不复制入口文件的硬约束**，改为链接。重复是矛盾的温床。
3. **给命令，不给形容词**。"运行 `python main.py`"优于"确保演示可用"。
4. **标注适用范围**。写清楚这是"公开核心"的行为，还是"某个可选模块"的行为——两者生命周期不同。
5. **沿用所在文件的语言**。中文、英文均可；代码块、路径和命令保持原样，不要求为统一语言重写旧文档。

## 新增一篇文档的步骤

1. 确认没有现成文档覆盖该主题（先看上面的表）。
2. 在 `docs/` 下建文件，写清用途、正文和相关入口；按需添加阅读条件。
3. 在本文件"全部文档"表中登记一行，填上"复核触发"。
4. 高频入口可同时补充 `AGENTS.md` 的文档路由；其他专题登记在这里即可。
5. 运行 `python scripts/check_docs.py`，修复断链和遗漏登记，按需处理篇幅提示。

## 审计

`scripts/check_docs.py` 检查内部链接和专题索引，提示篇幅与阅读条件问题。它不能验证文档描述是否符合代码，人工仍需核对具体命令和运行边界。

维护者可在发布或定期维护时修正失效内容、合并重复主题。贡献者无需为每次修复维护全仓进度日志；任务与证据放在对应 Issue / PR，较长交接可按需使用根目录的 `session-handoff.md` 模板。
