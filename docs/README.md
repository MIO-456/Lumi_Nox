# 文档地图

> **何时读**：你想知道"这件事该看哪份文档"，或准备新增 / 删除一份文档。
> **何时不用读**：已经知道自己要读哪一篇，直接去读。
> **复核**：每季度一次，或 `docs/` 新增 / 删除文件时（`python scripts/check_docs.py` 会提示遗漏登记）。

## 为什么不是一个大文件

把所有规则塞进 `AGENTS.md` 会出现五个可预期的问题：吃上下文预算、关键约束被埋在中间而忽略、硬约束与建议分不清、只增不减、新旧规则互相矛盾。所以这里按"用什么、什么时候用"拆开：

```
L1  入口      AGENTS.md            ~140 行   只做路由：概览 + 硬约束 + 文档索引
L2  专题      docs/*.md            50-150 行 一个主题一篇，按需加载
L3  状态      feature_list.json    —         当前任务与证据
              progress.md          —         跨会话交接
L4  验证      init.sh / init.ps1   —         编译 + 测试 + 文档体检
```

一条规则只在一个地方定义。入口文件写"必须遵守"，专题文档写"怎么做、为什么、什么时候可以删"。

## 每篇文档的元信息

新增或改动专题文档时，标题下保留三行引用块，回答三个问题：

```markdown
> **何时读**：<触发条件，具体到任务>。
> **何时不用读**：<避免误加载的场景>。
> **复核**：<时间点 或 明确的失效信号>。
```

- **何时读**决定路由表能否工作：写得含糊，agent 就只能在错误的时间加载错误的文档。
- **复核**是过期机制。没有失效信号的文档会永久留存，这正是"指令膨胀"的来源。
- 判断标准：如果删掉这篇文档，读者会犯什么错？答不上来就该删。

## 写作规则

1. **一篇一主题，50-150 行**。超过 150 行说明混了两个主题，拆开。
2. **不复制入口文件的硬约束**，改为链接。重复是矛盾的温床。
3. **给命令，不给形容词**。"运行 `python main.py`"优于"确保演示可用"。
4. **标注适用范围**。写清楚这是"公开核心"的行为，还是"某个可选模块"的行为——两者生命周期不同。
5. **中文为主，标识符保留英文**。代码块、路径、命令保持原样。

## 新增一篇文档的步骤

1. 确认没有现成文档覆盖该主题（先看上面的表）。
2. 在 `docs/` 下建文件，写元信息、正文、至少一条回链。
3. 在本文件"全部文档"表中登记一行，填上"复核触发"。
4. 如属于高频任务，在 `AGENTS.md` 第 4 节路由表加一行；低频任务只登记在这里。
5. 运行 `python scripts/check_docs.py`，确认链接与行数都通过。

## 审计

`scripts/check_docs.py` 自动检查：内部链接可达、单篇行数超预算、入口文件行数、文档表遗漏登记。
人工每季度做一次：删除已失效条目、合并重复主题、把入口文件里"其实很少用到"的规则移回专题。
