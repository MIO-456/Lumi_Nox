# 公开中控与五子棋

> **何时读**：想按节目单运行开场、聊天、五子棋和收尾，或贡献一个活动适配器。
> **何时不用读**：只测试手动对话时，读 [公开宿主](PUBLIC_HOST.md)。
> **复核**：节目时序、活动生命周期或控制 API 变化时。

公开中控使用 `core/program/` 的节目计时、推进、转场和完成判断。正式导演的 I/O 适配留在私人项目；公开版由 `public_host/program.py` 把同一调度层接到通用语音会话和网页五子棋。它提供可运行的节目流程，不包含正式角色资产、商业游戏安装环境、平台账号或私人 OBS 场景。

## 跑第一场

在仓库根目录执行：

```sh
python -m pip install aiohttp
python -m public_host
```

1. 打开终端给出的地址，默认 `http://127.0.0.1:8765`。
2. 点击“体验完整节目”，使用内存中的独立双角色临时配置，不覆盖已保存配置。
3. 观察舞台上的开场→聊天→五子棋→聊天→收尾。五子棋阶段同屏显示棋盘、自动落子和比分；也可打开独立游戏画面。
4. 要使用自己的角色、服务或节目单，先停止，再展开设置、保存配置并点击“开始节目”。五子棋需两位名字不同的启用角色。

演示中的模型返回固定示例，语音无声、每条模拟播放约 2 秒，界面记录“演示完成”；五子棋的规则、落子、计分和 HTTP 网页服务实际运行。五子棋采用已有规则算法，不调用语言模型下棋。换成真实服务后，聊天及游戏解说才使用你配置的模型、TTS 和 Python 播放设备；浏览器不播放音频。详见 [服务配置](PUBLIC_HOST.md#2-接入自己的模型和声音)。

单次短场可设为开场 5 秒、聊天 10 秒、五子棋 30 秒、聊天 10 秒、收尾 5 秒。五子棋沿用临近截止提前结算的规则，测试建议给它至少 20 秒。开场、结果播报或收尾仍在播放时，会等待对应请求的终态；时长不是强行截断音频的期限。

## 控制规则

| 操作 | 行为 |
|---|---|
| 开始节目 | 校验配置，再按顺序准备和激活第一环节；准备时间不计入新环节时长 |
| 下一环节 | 收束当前环节，活动确认停止后进入下一段；最后一段后结束 |
| 收尾 | 进入节目单最后的收尾段，再结束 |
| 立即停止 | 取消等待和当前发言，清理游戏；不额外生成告别话 |
| 手动对话 | 保留原来的输入驱动会话，不运行节目单和自动聊天 |

聊天环节会自动提交一条话题，完成后等待配置的间隔再继续；不会按定时器不断堆积请求。手动消息与游戏解说共用一个语音执行器。切段撤销旧环节的请求，迟到的模型结果不能在新环节继续播放。

“清理未完成”意味着仍保留资源所有者，不允许开始下一场或覆盖配置。查看具体错误，排除原因后再次点“立即停止”重试。取消时立即清除当前字幕；正在等待的模型请求仍可能等到超时才结束。多个页面共享同一场节目，刷新可恢复当前状态，关闭页面不会停止后台节目；结束后在终端按 Ctrl+C 退出宿主。

## 端口与画面

控制页默认 8765；五子棋默认 8791，在节目高级设置中可改。两者都仅绑定本机。五子棋底座在同一场节目中复用，退出活动时隐藏，节目结束时关闭；端口冲突会报错，不接管或关闭别的程序。

需要录制或推流时，可由使用者把活动 URL 添加为 OBS 浏览器源，建议 1920×1080。当前公开中控不自动控制 OBS 场景、开播推流，也不接 B 站弹幕、麦克风 ASR、记忆或私人游戏库。通用聊天/TTS/VTS 已有接线，其他能力需要各自适配器；不能把本地节目跑完等同于平台直播验收通过。

## 给贡献者的接入点

- `core/program/flow.py`：计时、tick、下一段与切换策略；每次推进最多一段。
- `core/program/transition.py`：固定转场次序与准备、激活、停止回执检查。
- `public_host/program.py`：公共宿主的 I/O 适配、阶段请求归属和准确语音终态。
- `public_host/activities/gomoku.py`：首个实际活动适配器。
- `minigames/`：复用的规则、整场计分、网页底座和结果发言机制。

新增活动先定义准备、激活、停止及最终关闭。返回 ready 前不能开始自动操作；active 要有实际运行证据；停止超时不能返回 stopped。游戏结果通过事件投递到节目线程，再送入统一 Session，避免在事件回调中持锁等待发言。

HTTP 控制为 `POST /api/start {"run_mode":"program"}`、`/api/next`、`/api/end`、`/api/stop`；原客户端不传 run_mode 时仍为 manual。体验按钮使用 `POST /api/demo {"run_mode":"manual"}`（聊天）或 `{"run_mode":"program"}`（完整节目），只构造临时配置。请求必须来自本机控制页，带 `Content-Type: application/json` 和 `X-Public-Host: 1`。新前端对已有运行的控制附带 `run_id`，旧场 ID 返回 HTTP 409。状态从 `GET /api/status` 的 program 字段读取；该字段在未建节目时为 null，请求轨迹与事件序号见[宿主指南](PUBLIC_HOST.md#3-停止打断和历史)。可用活动从 `GET /api/activities` 查询，五子棋依赖可用性从 `GET /api/capabilities` 查询。

改动后运行统一检查 `./init.ps1` 或 `bash ./init.sh`。安装 aiohttp 后还应跑 `python -m unittest discover -s tests -p 'test_public_gomoku*.py' -v`，并用浏览器确认一次实际落子、结算和回聊天。真实模型、声音、VTS 和 OBS 的验证应另记，不能用 demo 结果代替。
