# 方向草稿：让角色回应观众点唱

状态：**需先选择范围；尚未发布为 Issue。** 以下两种方案是不同工作量的候选，尚未确定采用哪一种。

## 先区分已有能力

直播系统已有观众点歌后播放歌曲的流程，也有演唱播前制作好的角色歌曲的节目。前者播放找到的音频，后者使用预先准备的角色演唱音轨。

新增方向是让观众的请求进入角色演唱环节。歌曲制作流程、角色声线和正式演唱接线目前未包含在公开库。

## 方案 A：点唱角色已经会唱的歌曲

观众从已有角色曲库点唱，程序匹配歌曲并给出结果，接受的请求按确认后的规则交给演唱环节。无需临时制作新音轨。

第一版可以用测试曲库和占位音频做独立演示，交付请求匹配、结果状态和队列。维护者先提供脱敏的曲库格式及演唱交接接口；具体排队和插播规则需在实现前确定。

验收时核对选中的歌曲与角色、找不到歌曲时的反馈、取消后的状态，以及旧请求不会在新环节误触发。此方案解决曲库点唱，不声称角色可以唱任何未制作过的歌。

## 方案 B：按请求制作新的角色演唱版本

收到一个尚未预制的歌曲请求后，在后台制作角色演唱版本，结果合格后再进入演出。先做技术原型，不承诺观众点任意歌曲后立即开唱；也不能用方案 A 的已有录音点播代替本方案验收。

### 第一版原型

先用自有或可用于该测试的歌曲素材、获授权的测试声线完成独立链路：输入歌曲人声与伴奏，生成目标声线演唱人声，输出混合母带和结果清单。不要求使用 Lumi/Nox 的真实声线。

制作作为后台任务运行，支持查询状态、取消和失败报告。演示要记录真实制作耗时、所需设备和失败情况，而不是只给最终成品。

维护者先提供脱敏的资产格式与测试样本，并与作者确定独立演示的运行方式。算法效果确认后，再由维护者协调接入点歌、曲库和演唱节目。

### 怎样验收

- 使用此前未预制的测试歌曲，从输入素材走到输出音轨和结果清单。
- 人工实听音色、唱词、节奏同步和混音；能生成文件不等于适合演出。
- 长任务不阻塞其他操作；取消或失败的任务不会稍后把结果加入演出。
- 报告实际耗时、设备条件和已知失败场景，为是否适合直播提供依据。

## 接直播前还需要确定

请求可接受哪些歌曲、等待期间如何告知观众、怎样排队、何时插入节目、失败后怎么回复，以及结果是否进入曲库。以上均为待讨论事项，本草稿不预设自动插播策略。
