# 方向草稿：增加一种绘画表现形式

状态：**先讨论表现形式和接口；尚未发布为 Issue。** 像素画是候选方案，具体形式待讨论。

## 已有能力与新增价值

直播系统已有文本模型输出坐标、多色曲线和逐笔绘画。因此本任务希望增加新的表达方式，例如逐格完成的像素画，而不是重复增加彩色线条或逐笔动画。

绘画生成、请求队列和舞台接线目前未包含在公开仓库。第一步可以做独立预览，正式接线由维护者提供条件后推进。

## 像素画候选方案的交付

- 一份容易理解的有限网格、调色板和绘制顺序数据说明。
- 可单独运行的网页渲染器、示例画作，以及逐格绘制的动画。
- 加载新作品、取消当前绘制、完成通知的明确行为。
- 预览和使用说明，展示适合直播观看的画面。

[现有画作消息、完成回执与合成样本](../PROTOTYPE_INTERFACES.md#绘画画作消息与完成回执)现已公开。维护者负责接入主题识别、队列和舞台；新表现形式仍需讨论数据扩展，不把原型作者自己设计的格式称为已确认的正式接口。

## 怎样验收

- 相同作品数据能稳定重现同一幅画。
- 切换作品后旧动画停止，不覆盖新作品；正常结束只发送一次完成通知。
- 在 1920×1080 预览中主体和文字清晰可读；不依赖真实角色素材。
- 渲染器验收后，再用实际模型生成的作品验证表现效果。固定示例渲染成功不能证明模型已经会生成合格像素画。

也欢迎先提出分镜、拼贴等其他形式，并提供一个能看懂效果的小样；每次只确定一种形式。
