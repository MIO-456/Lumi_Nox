# 方向草稿：接入一款适合角色互动的新游戏

状态：**先讨论选型和接口；尚未发布为 Issue。** 建议在范围确认后使用 `help wanted`，不把整项接入标成新手小任务。

## 想带来的变化

增加一款观众看得懂、角色有机会互动的新游戏。首轮只选一款，先证明它能独立运行、能接收程序动作，再接入直播。

合作扫雷可以作为候选例子：角色轮流分析并操作同一棋盘。它不是已经确定的选型，作者也可以提出其他游戏，并说明玩法和适合直播的理由。

## 先讨论什么

- 游戏名称、源码或控制项目链接、复用条件；需要用户自行安装什么。
- 角色是单人操作、轮流合作还是对战，观众能看到什么变化。
- 能否用程序读取局面和执行动作；隐藏信息如何避免泄露给角色。
- 第一版交付到哪一步，以及哪些接线需要维护者提供。

## 第一版交付

选型确定后，交付独立规则或桥接模块、可见画面和最小演示。演示应能新开一局、输出角色可见局面、列出合法动作、执行动作和判断胜负。提供启动说明与一段实际运行记录。

[最小游戏规则接口和离线数据示例](../PROTOTYPE_INTERFACES.md#新游戏规则与公开局面)现已公开。示例没有实现游戏宿主；作者可用自己的独立运行器验证规则，维护者负责后续提供正式接线条件。不要依赖尚未公开的导演或角色配置。

## 怎样验收

- 按文档可以独立完成一局，动作造成的变化和结果在画面中看得清。
- 非法、重复或上一回合迟到的动作不会误改当前局面；重开后状态正确。
- 角色只收到规则允许公开的信息。例如扫雷不能把未揭开的雷位交给决策者。
- 维护者提供接口后，再验证角色解说、节目启停和直播画面；独立原型通过不等于正式直播已验收。

第一版不要求作者同时改造主播主程序、音频系统和导演。
