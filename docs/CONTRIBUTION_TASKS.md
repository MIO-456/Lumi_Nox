# 可以一起做什么

[返回首页](../README.md) · [如何贡献](../CONTRIBUTING.md) · [快速开始](GETTING_STARTED.md)

我们优先寻找能改善直播内容的技术贡献，也欢迎运行测试、问题复现、教程与演示。第一次参与不需要先申请加入团队。

下面分清两种状态：**可独立开始**的工作只依赖公开代码；**先讨论方案**的方向还需要确定范围或由维护者提供接口。先在 [Issues](https://github.com/MIO-456/Lumi_Nox/issues) 搜索是否已有同一任务，没有的话可以提出建议；一个建议被讨论，并不代表已经承诺进入正式直播。

## 节目功能方向：先讨论方案

这三篇是准备讨论的 Issue 正文草稿，尚未发布为远端 Issue。不要把它们当成已实现功能、已确定的节目单或已公开的插件接口。

| 方向 | 希望增加的价值 | 第一次可以交付什么 |
|---|---|---|
| [接入一款新游戏](issue-drafts/new-game.md) | 给角色增加值得观看和互动的游戏环节 | 一款候选游戏的规则、公开局面、动作和独立演示 |
| [绘画的新表现形式](issue-drafts/drawing-presentation.md) | 让绘画环节有新的视觉表达，例如像素画 | 一种表现形式的数据示例和可单独预览的渲染器 |
| [让角色回应观众点唱](issue-drafts/requested-singing.md) | 观众可以请求角色演唱歌曲 | 先确定曲库点唱或按请求制作，再交付对应的独立原型 |

这些方向所需的正式直播导演、画板、演唱接线目前不在公开库。**维护者负责先提供经确认的最小接口、测试样本和验收方式，再推进需要这些接口的实现。**外部作者不需要获得私有仓库、人设或真实声线才能提交方案；也可以先展示自己已有的独立作品。

## 可独立开始：交互式终端演示

当前 `python main.py` 会自动跑完固定场景。可以增加一个手动输入弹幕的可选模式，让读者自己试“点名谁，谁接话”。

- **起点**：`main.py`、`speaker_scheduler.py`，见[快速开始](GETTING_STARTED.md)。
- **交付**：输入一条消息，经真实调度器选择角色，由占位脑返回示例回复；提供继续下一轮和退出的方法。
- **验收**：分别点名 Lumi、Nox 时路由正确；无点名时保持正常轮换；退出干净；原来的默认演示和现有检查继续通过。
- **范围**：仍然是无需密钥、终端无声的演示，不接真实模型或直播服务。开始前在 Issue 留一句准备采用的交互方式，便于避免重复工作。

## 可选维护工作：Windows 自动检查

目前每次提交或 PR，GitHub 会在一台临时 Ubuntu 机器上运行公开核心的检查。可以补一台临时 Windows 机器，运行同样的命令，提前发现路径、编码等平台差异。这不会操作维护者的直播电脑。

交付只涉及现有 CI 的平台配置及确有必要的兼容修正；两个平台都要通过现有编译和测试。通过后说明的是这部分公开检查兼容两个系统，不代表整套直播已跨平台验收。

## 不写代码也能参与

- 按上手指南运行，报告系统、Python 版本、实际步骤和出错位置。
- 为一个公开模块制作教程或演示，说明使用的版本以及需要的环境。
- 提交带复现步骤的问题，或帮助核对已有问题是否已经解决。

被采用的贡献可以在更新说明中署名；独立教程和作品可保留原作者链接。是否用于直播、发布介绍视频，需结合实际效果另行确认。
