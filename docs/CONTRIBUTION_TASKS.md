# 可以一起做什么

> **何时读**：想贡献但不确定从哪开始，或判断一个方向是否"可独立开始"。
> **何时不用读**：已经在做具体任务——直接看 [CONTRIBUTING](../CONTRIBUTING.md) 的提交流程。
> **复核**：任务被认领、方向变化，或某个"先讨论方案"已获结论时。

[返回首页](../README.md) · [如何贡献](../CONTRIBUTING.md) · [快速开始](GETTING_STARTED.md)

我们优先寻找能改善直播内容的技术贡献，也欢迎运行测试、问题复现、教程与演示。第一次参与不需要先申请加入团队。

下面分清两种状态：**可独立开始**的工作只依赖公开代码；**先讨论方案**的方向还需要确定范围或由维护者提供接口。先在 [Issues](https://github.com/MIO-456/Lumi_Nox/issues) 搜索是否已有同一任务，没有的话可以提出建议；一个建议被讨论，并不代表已经承诺进入正式直播。

## 节目功能方向：先讨论方案

这三篇是方向草稿，具体范围与认领以关联 Issue / PR 为准；不要把它们当成已实现功能或已确定的节目单。[最小接口与离线样本](PROTOTYPE_INTERFACES.md)现已提供，可供独立原型参考；它们还不是完整插件系统。

| 方向 | 希望增加的价值 | 第一次可以交付什么 |
|---|---|---|
| [接入一款新游戏](issue-drafts/new-game.md) | 给角色增加值得观看和互动的游戏环节 | 一款候选游戏的规则、公开局面、动作和独立演示 |
| [绘画的新表现形式](issue-drafts/drawing-presentation.md) | 让绘画环节有新的视觉表达，例如像素画 | 一种表现形式的数据示例和可单独预览的渲染器 |
| [让角色回应观众点唱](issue-drafts/requested-singing.md) | 观众可以请求角色演唱歌曲 | 先确定曲库点唱或按请求制作，再交付对应的独立原型 |

基础对话、语音与可选嘴型已经接入[公开宿主](PUBLIC_HOST.md)，新模块可用 `Session.submit_speech()` 提交解说。这些节目方向的活动注册、启停和回聊天尚未统一接通，画板与演唱运行服务也未公开。**维护者仍负责确认具体方案、补充所需活动宿主和正式接线，并完成直播验收。**外部作者不需要获得私有仓库、人设或真实声线才能提交独立原型。

## 可独立开始：公开宿主的复现、测试与教程

运行 `python -m public_host` 并选择离线演示，验证自定义单/双角色、逐条输入、直接朗读和停止；也可围绕一个明确问题提交必要的回归测试，或写清使用环境的教程。真实服务和设备验证要单独说明，不需要提交个人配置或凭据。已有相同任务时在 Issue / PR 协调分工。

## 可选方向：交互式终端演示

当前 `python main.py` 会自动跑完固定场景，而网页宿主已经支持手动输入。若有不使用浏览器的明确需求，仍可讨论给终端入口增加交互模式；这不是所有贡献者都需要先做的任务。

- **起点**：`main.py`、`core/speaker_scheduler.py`，见[快速开始](GETTING_STARTED.md)。
- **交付**：输入一条消息，经真实调度器选择角色，由占位脑返回示例回复；提供继续下一轮和退出的方法。
- **验收**：分别点名 Lumi、Nox 时路由正确；无点名时保持正常轮换；退出干净；原来的默认演示和现有检查继续通过。
- **范围**：仍然是无需密钥、终端无声的演示，不接真实模型或直播服务。开始前在 Issue 留一句准备采用的交互方式，便于避免重复工作。

## 已有维护能力：Windows 自动检查

GitHub Actions 已配置 Ubuntu 与 Windows 临时机器，运行相同的公开检查，无需再创建“增加 Windows job”的任务。可以针对实际失败提交路径、编码等兼容修复；CI 不会操作维护者的直播电脑。

是否通过以对应提交的 Actions 结果为准。两个平台的自动检查通过，只说明被测公开能力通过，不代表真实语音、游戏或整套直播已跨平台验收。

## 不写代码也能参与

- 按上手指南运行，报告系统、Python 版本、实际步骤和出错位置。
- 为一个公开模块制作教程或演示，说明使用的版本以及需要的环境。
- 提交带复现步骤的问题，或帮助核对已有问题是否已经解决。

被采用的贡献可以在更新说明中署名；独立教程和作品可保留原作者链接。是否用于直播、发布介绍视频，需结合实际效果另行确认。
